## Problem

The Fenix container's Supervisor TUI (started via the `supervisor-run` branch
of `docker/entrypoint.sh`) blocked unattended runs on two Claude Code surfaces:

1. **"Auto-update failed: no write permission to npm prefix"** status-line
   banner — the image's npm prefix is read-only by design (the CLI is pinned
   via `npm install -g @anthropic-ai/claude-code@$CLAUDE_CODE_VERSION` in the
   Dockerfile), so the auto-updater can only fail there.
2. **"Teach auto mode about your environment?"** modal popup (the
   `/auto-mode-setup` offer).

## Research (mechanism → source)

| Mechanism | Source |
|---|---|
| `DISABLE_AUTOUPDATER=1` is the documented switch that disables the auto-updater; the npm-prefix failure banner is the documented startup-notice case | Official docs: https://code.claude.com/docs/en/setup ("Disable auto-updates"); verified in the installed CLI 2.1.314 binary — `DISABLE_AUTOUPDATER` is in the CLI's env-var table and the updater-disable check consults it FIRST (`if (envOverride) return {type:"env"}`) before falling back to the `.claude.json` `autoUpdates` key |
| "Teach auto mode about your environment?" show-gate: shows only when auto mode is active AND the effective autoMode config has no `environment` rules AND `numStartups >= 5` AND `autoModeEnvSetup.denials >= 5`; suppressed permanently when `.claude.json` has `autoModeEnvSetup.dismissed === true`, and for 7 days after `autoModeEnvSetup.dismissedAt`. The "Don't show again" option writes exactly `{ dismissed: true }` ("later" writes `dismissedAt`) | Decompiled from CLI 2.1.314. It is a `.claude.json` key, NOT a settings.json key — same class as the FOC-810 flags |

## Shipped

  DISABLE_AUTOUPDATER=1` alongside the existing exports, with a FOC-1066
  comment citing the docs page and the CLI 2.1.314 verification. No other
  entrypoint branch changed.
- `scripts/fenix-claude-prefs.mjs`: `applyClaudePrefs` now also records the
  dialog dismissal — `autoModeEnvSetup = { dismissed: true, dismissedAt: <epoch

  note). The atomic-write and "never overwrite unparseable file" behaviour are
  untouched, and the one-line stdout summary is unchanged (a test asserts it).
- `scripts/fenix-container-helpers.test.mjs`: the fresh-config case asserts
  `autoModeEnvSetup.dismissed === true` and a numeric `dismissedAt`; the
  preservation/idempotency case seeds `autoModeEnvSetup: { denials: 5 }` and
  asserts `denials` survives the merge with `dismissed === true`.
- `scripts/supervisor-headless-env.test.mjs` (new, self-contained harness):
  asserts the `supervisor-run` case of `docker/entrypoint.sh` exports
  `DISABLE_AUTOUPDATER=1`, that the export stays scoped to that branch (no
  other case, no global export), and that the FOC-1066 rationale comment is
  present.

## VM UAT checklist (container)

1. Start the container and attach the Supervisor pane (`fenix attach`).
2. Confirm the status line shows NO "Auto-update failed: no write permission
   to npm prefix" banner.
3. Confirm NO "Teach auto mode about your environment?" dialog appears.
   Note: the dialog can only ever appear after >= 5 auto-mode denials AND
   >= 5 startups, so on a fresh volume the banner is disproven trivially and
   the dialog is proven by the dismissed flag itself.
4. Check `.claude.json` in the supervisor config dir
   (`$LA_SQUAD_HOME/supervisor/.claude.json`, or the session dir for a managed
   task session) contains `autoModeEnvSetup.dismissed: true`.
5. Optional: `claude doctor` in the pane reports auto-updates disabled by env
   (`DISABLE_AUTOUPDATER`).
