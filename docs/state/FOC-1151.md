## 2026-11-02 — the four fixes

### 1. Foreign optionLabel refused (`scripts/supervisor-gate.mjs`, `answerHold`)

An `optionLabel`, when given, must equal one of the hold's OWN option labels;
otherwise `invalid-answer` (HTTP 400). The Cockpit sends the label of the
option the answer came from, so a label matching nothing is a bug on the
sending side, not a value to record. `optionLabel` null passes untouched (the
CLI and older callers). The match scans EVERY option (needsText or not); the
refusal order is unchanged: not-found → already-answered (409) → label checks
(invalid-answer/400) — the foreign-label check and the FOC-1109 bare-label
refusal are mutually exclusive conditions (the bare-label refusal fires only
when NO optionLabel is given).

One existing assertion was updated to the new contract:
`supervisor-gate-answer.test.mjs` "hold optionLabel: stored when given…" used
`optionLabel: "Provide the values"` against a seeded hold whose only option is
"wznów" — now stores `"wznów"` (the hold's own label). Everything else in both
suites already sent own labels or nothing.

### 2. CLI `--optionLabel` (`scripts/supervisor-gate.mjs`, `cmdAnswer` hold branch)

`answer --hold <id> --text "..." [--optionLabel "<label>"]` carries the label
into `answerHold`, so a needsText hold can be answered by label from the CLI
exactly like from the Cockpit. Validated by `answerHold` against the hold's
own options (item 1). Usage comment updated.

### 3. `parseOption` carries `needsText` (`scripts/supervisor-gate.mjs`)

A `--option` JSON with `needsText: true` now produces a hold option that
retains the flag, so a CLI-created needsText hold enforces the FOC-1109
bare-label refusal end to end (the previously documented limitation is
lifted). Only strict `=== true` is carried; any other value (false, absent,
truthy non-boolean like `"yes"`) is dropped — a string must not smuggle a
half-flag past the answer rules. `validateHoldStore` ignores the field either
way (no validation change). The stale FOC-1109 limitation comment at the
return shape was replaced.

### 4. Store-write failure → 500 (`scripts/supervisor-gate.mjs` + `scripts/cockpit-routes.mjs`)

`answerHold`'s `patchHold` catch used to rewrap ANY write failure as
`invalid-answer` (HTTP 400) — a server fault wearing a client error's clothes.
It now throws `answerError("store-write", …)`; `answerErrorStatus` maps
`store-write` → 500 explicitly (both answer routes — gates and holds — share
the mapping; a gate's own write failure was already an uncoded Error → 500).
Client-shaped refusals stay 400: blank text, bad-id, foreign optionLabel,
bare-label.
