## 2026-11-02 — design decisions (the AC's open shapes)

1. **Evidence flag shape**: a JSON flag, mirroring `--ran` exactly —
   `--container-run '{"cmd":"...","exit":0,"outputRef":"..."}'` (non-placeholder cmd, integer
   exit, non-placeholder outputRef → `checkOutputRef`, the FOC-1170 path REUSED — win32
   case-folded containment included, no second path check forked). Reason: a container run IS a
   command the TEST child ran; the same audit contract (output saved where the run can read it)
   should cover both, and the record consumer (delivery, FOC-946 reflector) already understands
   `{cmd, exit, outputRef}`.
2. **The unavailable branch**: `--container-unavailable "<why>"` (non-placeholder, ≥4 chars after
   the same NON_EVIDENCE filter) → record field `containerRun: "unavailable: <why>"` — the exact
   string form the ticket pins. Giving both flags is refused (`container-run-contradiction`): the
   container either ran or it did not.
3. **Refusal code**: `test-pass-without-container-run` (mirrors
   `review-pass-without-evidence-run`). One code covers both branches — seam true with nothing
   cited, and seam false with a bare missing field; the refusal JSON carries `dockerAvailable`
   so the child sees which situation it is in. A fail verdict does not need the field (the same
   asymmetry `--ran` has); a `--container-run` CITED on a fail is still shape- and
   existence-checked (FOC-1170 decision #1, mirrored).
4. **The seam**: `LA_DOCKER_AVAILABLE=1|0` env override, checked first; unset → the daemon is
   probed with `docker info --format {{.Server.Version}}` (20 s timeout) — "could this host run
   the Fenix container", which `docker --version` (CLI present, daemon dead) does not answer.
   Env var (not an in-process export) because `record` runs as a SPAWNED process in the suite —
   a module-level seam cannot reach it, and this repo's established seams are env-shaped
   (REVIEW_DRY_RUN, FOC-1169). The probe runs only for a test-squad pass that lacks a cited run.
   Documented softness: an env var can be faked by the recording child — but so can every flag;
   the gate's job is to kill OMISSION, and the record still states why nothing ran, which is
   what delivery reads.
5. **What the deterministic security step runs** (`agents/review/CLAUDE.md` §3, all cited with
   `--ran`): `node scripts/security-scan.mjs` (secretlint + semgrep, FOC-285),
   `node scripts/security-scan.test.mjs` (the scanner's contract suite, which also scans the real
   tree as the end-to-end negative case), and `node scripts/egress-screen.mjs check --body-file
   <round file>` (the round file is outbound text — screened before it is published).
6. **Role-table home**: `docs/agents/role-set.md` (NEW file — docs, not a test file, so the
   docs-count guard's 215 test-file count is unchanged; verified). Chosen over
   `docs/HOW-TO-RUN-AGENTS.md` §3 because that section is a launcher↔model cheat sheet with
   stale hardcoded model names, not a role contract.
7. **Canonical rule sentences** (the FOC-1170 pattern — role doc is canonical, templates carry a
   one-line pointer): REVIEW one-strong-pass sentence = `agents/review/CLAUDE.md` §3; TEST
   container-run sentence = `agents/test/CLAUDE.md` §4b; DEV lead-writes sentence =
   `agents/dev/CLAUDE.md` `<dev_squad>` note + step 3. The hand-authored Supervisor kickoff now
   has its instruction in `agents/supervisor/CLAUDE.md` §3 Spawn (the supervised spawn path has
   no template file). `config/dry-run-kickoffs.json` review line said "parallel
   first-pass/security/deep review" — updated, it is a kickoff surface that contradicted the rule.
