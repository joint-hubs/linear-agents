## 2026-11-01 — bug: a task session's claim was invisible on the Work board

### Symptom

While FOC-1055 ran as a task session, its Work board card had no "Open cockpit"
link and the panel showed Ready / No events / Start as if nothing were running.

### Recon (verified in source)

The board payload (`GET /api/work/tickets`, work-routes.mjs) already attaches
`claimedBy` per ticket (the task-sessions store's active owner via
`readTaskClaims` / `claimFor`, with `live` = owning pid provably alive), and the
UI already renders everything the ACs ask for from `ticket.taskKey`
(TicketCard's "Open cockpit →" guard, Work.jsx `panelTaskKey`, TicketPanel's
"Open cockpit" button). ROOT CAUSE: the board ticket entries never carried
`taskKey` — `touchedTicketEntry` / `readyTicketEntry` in work-board.mjs do not
set it — so every downstream guard saw `undefined` and stayed silent. The
Start-preview route already derives the canonical key server-side
(`taskKeyOf(issue) = resolveTaskKey({ workspace, issueId })`, display
identifier, never a uuid).

### Fix

Server-side join where the lease is already attached: work-routes.mjs now sets
`ticket.taskKey = taskKeyFor(ticket.taskId, workspace)` in the same loop that
sets `ticket.claimedBy` — `taskKeyFor` is the `resolveTaskKey` resolution
extracted from `claimFor` (same try/catch tolerance: a non-canonical id is
`null`, never a guess; workspace is the server's own `workWorkspace()`, never
client-supplied). No change to work-board.mjs was needed. UI: new pure model
function `sessionClaim(ticket)` in workModel.js (sibling of `claimTag`) spells
the lease out for the panel — full session id, store status, `live` — Work.jsx
passes it down, TicketPanel renders the claim line, suppresses the Start button
when `claim.live`, and shows the cockpit link (existing guard, now fed). The
card needed no code change — its guard works as designed once the payload
carries the key.

### Session-events scope decision (AC2) — honest minimum, NOT taken

The richer version (panel timeline fed from the `/api/supervisor/sessions`
registry, cockpit-routes.mjs) would need new cross-host plumbing from the board
host to the session registry; the contract forbids that cost for a read-only
affordance fix. Shipped minimum: the panel shows the live claim line
("claimed by sup-xxxx (running, live)"), suppresses Start for a live-claimed
ticket, and links the cockpit. The Timeline keeps reading ticket detail
(buildTicketDetail/buildTimeline) — a task session's turns are not Fenix run
facts, so "No events yet" stays honest and nothing is invented.
