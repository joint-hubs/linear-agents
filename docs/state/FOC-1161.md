## 2026-11-01 — Part 2: drop the 160-char question cut in supervisor briefing holds

### Part-2 decision

`scripts/supervisor-status.mjs` `briefingHolds()` carried the hold question
sliced to 160 chars (`question: String(h.question).slice(0, 160)` — the only
160-slice in scripts/). The briefing payload now carries hold questions in
full (`question: String(h.question)`).

- **No test asserted the truncation.** Grep over scripts/ for `160` shows the
  other 160-char caps (`supervisor-conversation.mjs` SUMMARY_CAP, the
  `augment-paraphrase` log slice) are unrelated; the holds briefing tests only
  asserted `typeof hold.question === "string"`. So there was no briefing test
  asserting the cut to update — a new one was added instead:
  `the briefing carries the hold question in full — no 160-char cut`
  (supervisor-status.test.mjs, holds section), feeding a 160+char question
  through `holdFixture` and asserting the briefing returns it verbatim.
- **Documented consumer check (FOC-1056):** `docs/state/FOC-1056.md` (UI
  note) documents the slice as a list-view convenience — "through
  `supervisor-status` sliced to 160 chars (list view) … will show only the
  key list line, hints visible in the Cockpit detail view". The Cockpit
  detail view already renders the full question verbatim, so the slice was a
  display shortcut, not a contract; removing it makes the list view match the
  detail view. No consumer depends on the cap.

### Before-list — tests that resolved the host run

- `scripts/agent-state.test.mjs:1451` (`cli: namespace and actor derive from
  the session env`) — leaked `LA_SUPERVISOR_CHILD="probe"` flipped
  `namespaceFromEnv` from `supervisor:run_1` to `child:run_1/probe`.
- `scripts/agent-state.test.mjs:1104` (`cli: usage errors exit 2 …`) — the
  namespace derived from the leaked host `LA_SUPERVISOR_RUN` /
  `LA_SUPERVISOR_CHILD`, so a usage error that must exit 2 exited 0.
- Both reach the leak through `cliEnv` (`agent-state.test.mjs:78`), which
  spread `process.env` straight into every CLI child env.
- Resolve suite (`agent-state-resolve.test.mjs`, `makeFixture()` env at
  :288-303) pinned `LA_SUPERVISOR_STATE_HOME`/`LA_AGENT_STATE_DB` but copied
  `process.env` without pinning `LA_DATA_HOME`/`LA_STATE_ROOT` and without
  stripping `FENIX_SUPERVISOR_SESSION_ID`; hook suite
  (`agent-state-hook.test.mjs` :110-135) already deleted
  `FENIX_SUPERVISOR_SESSION_ID` but not the two state roots. Under the fake
  host both could resolve the live `current-run.json` via the `"current-run"`
  resolver (`agent-state-resolve.mjs:153-157`).

### Fix

- `scripts/agent-state.test.mjs` — `cliEnv` now strips a pinned
  `HOST_SESSION_SEAMS` list (`LA_SUPERVISOR_RUN`, `LA_SUPERVISOR_CHILD`,
  `LA_TASK_OWNER`, `FENIX_STAGE`, `FENIX_SUPERVISOR_SESSION_ID`,
  `LA_SUPERVISOR_STATE_HOME`, `LA_STATE_ROOT`, `LA_DATA_HOME`,
  `LA_AGENT_STATE_NOW`) before spreading `process.env`; the two direct
  `{...process.env, LA_AGENT_STATE_DB: dbPath}` spawns (former ~:1014, ~:1026)
  now use `cliEnv(dbPath)`.
- `scripts/agent-state-resolve.test.mjs` — fixture env strips
  `LA_DATA_HOME`/`LA_STATE_ROOT`/`FENIX_SUPERVISOR_SESSION_ID` (defense in
  depth for the `"current-run"` resolver path).
- `scripts/agent-state-hook.test.mjs` — fixture env additionally pins
  `LA_DATA_HOME`/`LA_STATE_ROOT`.
- `scripts/agent-state-isolation.test.mjs` (NEW) — strips every `NODE_TEST*`
  key from the grandchild env (the parent `node --test` stamps
  `NODE_TEST_CONTEXT`, and a grandchild that inherits it skips every file:
  "run() is being called recursively"), spawns the three suites as
  `node --test` children under the fake live host, and asserts a recursive
  byte snapshot (`snapshotTree`) of the fake host is unchanged. Registered in
  `scripts/test-lanes.json`; both `docs/supervisor-e2e-checklist.md` count
