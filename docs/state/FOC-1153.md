## 2026-11-01 — the incident, and the two halves of the fix

docs/HANDOFF.md §incident (2026-11-01): a child created a `node_modules`
JUNCTION into the main checkout; `git worktree remove --force` followed it and
emptied the main checkout's node_modules — twice in one day. Two halves:

1. **Provisioning** — the child improvised an install because spawn handed it a
   tree without node_modules. Spawn now provisions deps itself, as real
   directories, before the child exists: no reason to link one in.
2. **Removal guard** — even with provisioning, a link can appear in a worktree
   (a child can still make one). The removal now unlinks reparse points AS
   LINKS before the destructive act, so git never follows them out of the tree.

### Platform facts, probed on this machine (win32, node 22.20.0, git for Windows)

- `lstatSync(p).isSymbolicLink()` reports a junction as a symlink AND as
  not-a-directory (`isDirectory() === false`) — so `existsSync` is never a
  sufficient "real node_modules" test.
- `rmSync(junction)` removes the link only; the target's content survives.
- **`git worktree remove --force` DOES follow junctions** — root-level
  (`node_modules`) and nested (`ui/node_modules`) both emptied an outside
  target directory. The red-first AC2 test reproduced the incident verbatim on
  the unmodified base.

### Provisioning design

- `installWorktreeDeps(worktree)` — `scripts/supervisor-lib.mjs` (added right
  after `withOwnership`, ~:2140). Two locations: the worktree root and `ui/`.
- **Hook point (spawn)**: `scripts/supervisor-spawn.mjs`, directly after the
  referenced-files check and BEFORE the CodeGraph launch-readiness section —
  after every free refusal (pinned state, prompt-file, referenced files), so a
  refused spawn never pays for an install; before the index preflight, so the
  codegraph sync sees the tree's final shape. Outside `ensureWorktree`'s
  integration lock on purpose: an install under the repo-wide lock would
  serialize every concurrent spawn behind one package manager.
- **Tolerance/skip rules** (per location, `installDepsAt`): no `package.json`
  → skip (`reason: "no package.json"`); `node_modules` present AND a real
  directory by lstat → skip (`"node_modules already present"`); present but a
  reparse point (or a stray file) → unlink the link only, record
  `replacedReparsePoint: true`, install fresh.
- **Command split** follows the merge tool (`supervisor-merge.mjs`
  `installIntegrationDeps`): `npm ci` with a lockfile, `npm install` without,
  both `--no-audit --no-fund`, `shell: true`, `maxBuffer` 64 MB — the same
  bounded-subprocess precedent.
- **Timeout budget**: `DEPS_INSTALL_TIMEOUT_MS = 300_000` (5 min). Bounded well
  under the merge tool's 900 s verify ceiling because spawn blocks the child
  launch; comfortably above this repo's own installs, which measure in seconds.
  Known accepted trade (same one the merge tool makes): a timed-out install
  leaves a node_modules a later ensure would skip as "already present"; the
  failure is in the record, never silent.
- **Failure reporting**: NOT fail-closed, mirroring the codegraph-readiness
  contract — a child that can still work without fresh deps is worth more than
  no child at all. Loud half: `console.error("[spawn] dependency install
  FAILED — the child starts anyway; see depsInstall in the spawn result ...")`.
  Durable half: a `depsInstall` record (per-location: skipped/reason/command/
  exitCode/timedOut/error/tail) in BOTH the registry entry and the spawn's
  final JSON output, beside `codegraph`.
- **DECIDED — ui/ is unconditional-when-present, not ticket-aware**: whenever
  `ui/package.json` exists, it is installed (or skipped on the rules above),
  regardless of what the child's task names. A child whose task touches only
  the root still needs the ui tree buildable, and the skip-or-install cost is
  seconds.
- **task-session-host call site** (`scripts/task-session-host.mjs`, the
  `ensure()` inside the session-workspace factory, ~:405): the same lib
  function drops in with no extra risk, so it IS applied — after
  `ensureWorktree`, outside the lock; the record rides on the memoized ensure
  result (`depsInstall` field), and a non-ok install logs one
  `console.error("task-session-host: dependency install did not complete ...")`
  line matching the host's existing error convention. The session starts
  anyway.

### Removal guard design

- `unlinkReparsePoints(worktree)` — `scripts/supervisor-cleanup.mjs`, called
  from `performRemoval` immediately BEFORE `git worktree remove` (both paths —
  recorded grant and two-key — converge there, so one guard covers both).
- **Windows reparse detection**: the repo idiom
  `lstatSync(p).isSymbolicLink()` — probed above; it reports junctions too.
- **Scan depth — depth 3, pruned**: top-level-only would have been
  insufficient (see probe: git follows NESTED junctions, and `ui/node_modules`
  is one of the two locations this same change provisions — a root-only guard
  would be self-inconsistent). The walk descends real directories to depth 3
  (root entries, their children, grandchildren), which covers
  `packages/*/node_modules` shapes too, and prunes descent into real
  `node_modules` directories (a package manager's domain, unbounded) — a
  handful of lstat calls per directory, no deep walk. Reparse points are never
  descended into; they are removed.
- **Failure mode**: a link that cannot be unlinked refuses the whole removal
  (`failJson`) — a git remove that would follow an unremovable link IS the
  incident. As with the existing git-failure path, the archive step has
  already run at that point; it is additive and the tree is left standing.
- **Report honesty**: a fifth list, `removedLinks`, in the removal JSON
  (`path — reparse point → target, unlinked before removal: git worktree
  remove follows junctions`), beside the existing `skippedLinks`/`skippedCache`
  lists — the links die with the worktree, but the list exists for the TARGET
  that kept its content.

### Tests

- AC1 — `scripts/supervisor-spawn.test.mjs`, through the REAL spawn path
  (`runSpawn`): the worktree's content must be what a child of THIS spawn
  actually receives, which `fixtureWorktree` alone cannot prove (it cuts a
  tree without running the provisioning hook at all — the merge suite needed
  its own end-to-end for the same reason). Fixture = the merge suite's
  offline-npm pattern: a `preinstall` that writes `fake-dep`, an empty
  lockfile `npm ci` accepts offline, manifests committed to the BASE commit
  (the tree is cut from HEAD — an uncommitted manifest never reaches it and
  the install would skip as "no package.json", testing nothing). Asserts
  node_modules exists at root and ui/, lstat says a real directory (not a
  reparse point), `fake-dep` resolves from the worktree root, and the spawn
  output carries `depsInstall` with `ok: true` and a non-skipped ui location.
- AC2 — `scripts/supervisor-cleanup.test.mjs`, through the cleanup CLI
  (`scenario()` + `approved()`): two junctions planted in the fixture worktree
  (root `node_modules` — the incident shape — and `linked-dep`), targets
  OUTSIDE the worktree carrying a sentinel; asserts the worktree is gone, the
  sentinel survives, and the report names the handled links. win32 junctions
  (`fs.symlinkSync(..., "junction")`, unprivileged); POSIX takes directory
  symlinks — the same lstat shape. Red-first on this machine (win32) where
  the incident platform is; on POSIX the red state cannot reproduce (git does
  not follow symlinks on removal), so there the test is a regression guard.
