## 2026-11-03 — the defect, and why no suite was red on it

`cmdRecordDelivery` (`scripts/supervisor-verdict.mjs`, the `--delivery` mode from FOC-1169)
recomputes `progressFingerprint` from the dev child's worktree AS IT IS NOW. For the
2026-11-01/02 backfill baseline most dev trees are already removed (FOC-1147, 1151, 1156,
1088, 1145, 1164, 1146) → `progressFingerprint` returns `diff: null` with `error` set
(`scripts/supervisor-lib.mjs:3001-3002`, the UNKNOWN branch), and `reviewFalsePass`
(`scripts/cost-quality.mjs`) never matches — its falsify rule requires
`v.fingerprintDiff != null && v.fingerprintDiff === row.fingerprintDiff`, and null never
matches anything. The baseline denominator sat at ~2 with a numerator that could not move.

No suite was red on this because no fixture ever removed the tree: every
`scenario()` in `scripts/supervisor-verdict.test.mjs` creates a real fixture worktree and
keeps it alive through the record call, so the recompute path always produced a real diff.
The gap was in the fixture world, not the assertion world — a test that simulates the
2026-11-02 baseline (dev worktree deleted before the backfill) had simply never been
written.

## 2026-11-03 — what changed, per item

### 1. `supervisor-verdict.mjs` — `--contradicts-round N` (backfill only)

- New flag on the delivery path, accepted ONLY together with `--backfill` — refused
  otherwise with the same shape as the `--recorded-at` coupling refusal (a live record's
  "now" fingerprint is the honest one; provenance without the backfill admission is
  meaningless). Validated as an integer N ≥ 1.
- With the flag, the record's fingerprint is NOT recomputed: `roundsFor(runId, taskId)` is
  read (before this record is written — the chain cannot contain itself), the record with
  `round === N` is found, and its fingerprint is copied verbatim — the five identity fields
  `diff`, `tests`, `combined`, `changedFiles`, `failingTests` — plus `source: "round-N"`.
  The copy replaces `progressFingerprint` entirely; `resolveWorkChild` still runs (fail-closed,
  unchanged — the registry entry must exist even though its tree may not).
- Refusals, fail-closed and named: round N does not exist (message carries the known
  rounds), round N is unreadable, round N's fingerprint has no `diff` (a copy of null would
  silently match nothing — the exact UNKNOWN the flag exists to stop recording).
- Without the flag, backfill recomputes exactly as before (the original code path is
  untouched, only nested in an `else`); the UNKNOWN warning and the
  "fingerprinted dev-N's tree" warning are on that path only. The copy path warns
  "fingerprint copied from round N of <taskId> (--contradicts-round N)" instead.
- Usage header updated (`[--contradicts-round N]` on the delivery line).

### 2. `cost-quality.mjs` — `reviewFalsePass` counts the named pair

- A REVIEW PASS round is falsified by a delivery FAIL whose `fingerprintDiff` matches —
  now EITHER a delivery verdict positioned after it (`recordedAt` order, unchanged) OR one
  that NAMES the round: `fingerprintSource === "round-" + row.round` (FOC-1194). The
  denominator (contradicted rounds) takes the union of both, deduped by row identity.
  Rationale: a backfilled record's `recordedAt` is the operator-typed truth of when it
  happened; the round reference, not the clock, is the authoritative link to the pass it
  contradicts. The tree-axis requirement is unchanged — a named FAIL with an unequal diff
  still proves nothing (UNKNOWN is not evidence, by position or by name).
- `DEFINITIONS.reviewFalsePass` text extended with the source-reference clause.

### 3. `work-board.mjs` — verdict rows carry `fingerprintSource`

- Pass-through of `record.fingerprint?.source` (`null` when unreadable or absent) —
  FOC-1169 did the same for `squad`/`fingerprint`/`reason`/`fingerprintDiff`: without it the
  quality signal is uncomputable from production data, fixtures only. Deliberately beyond
  the kickoff's file list, flagged here; the record shape itself is untouched.
- The timeline is untouched; the field only feeds the quality signal.

## 2026-11-03 — ambiguity calls the AC left open (and what was chosen)

- **Which record can round N be?** Any verdict record in the same `roundsFor` chain —
  typically the REVIEW pass. The copy builds `source: "round-N"` from the round it copies,
  so a chain-of-copies names its direct source. If round N is itself a backfilled copy,
  its `diff` is by construction the original pass's — the pair still matches.
- **Does `--contradicts-round` relax `resolveWorkChild`?** No — the registry entry must
  exist (fail-closed, unchanged); only the fingerprint READING changes. The red test runs
  against a registry whose dev child's worktree path no longer exists on disk.
- **Self-reference refused by construction**: the record being written is not yet on disk,
  so `--contradicts-round` naming the round being recorded reads "does not exist" —
  fail-closed.
- **The pair counting when `at` order and the named round disagree**: both are counted
  (union, deduped); the numerator still requires the tree axis to match.
