## 2026-11-01 — Injected clock for the /api/team routes tests; wall-clock-independent fixtures

`scripts/team-routes.test.mjs` spawns the REAL telemetry-server (port 7393)
against the shared team fixture, whose dates are fixed ISO strings around
NOW = 2026-10-18T12:00Z. The server builds the payload with
`now: Date.now()` (team-routes.mjs, no injection path), so once the wall
clock passed 2026-11-17 the fixture's 30d-window data aged out and two checks
failed for real: the overall supervisor block (supervisor.costUsd 0 vs 6) and
the milestone=M8 group totals ({69,49,2,3} vs {75,51,2,4}). Red on base
confirmed exactly those two (13/15; evidence below).

Mechanism — an injected clock, not `period=all`: the 30d-default code path
stays covered end-to-end, and the fixture dates are self-consistent with the
clock that windows them, so nothing can age out for ANY wall-clock date:

- `scripts/team-routes.mjs`: TEST-ONLY seam `FENIX_TEAM_CLOCK_MS` (integer
  ms) read where the payload's `now` is produced. Guarded by `NODE_ENV=test`
  (the same rule as `FENIX_LINEAR_FAKE_FILE`): unset, or set outside a test
  run, the payload's now is `Date.now()` — production unchanged. Shape
  follows the sibling clock seams (work-routes/cockpit-routes in-process
  setters), but env-based because a spawned server child cannot reach module
  setters.
- `scripts/team-model.test.mjs`: `seedTeamFixture` re-anchors every seeded
  date (runs.started_at, run_task_links.valid_from, usage observed_at/
  created_at) from its NOW offset to the caller's `now`. Default
  `now = NOW` re-anchors to the original strings exactly, so the unit layer's
  NOW-derived expectations are untouched (15/15 unchanged).
- `scripts/team-routes.test.mjs`: ONE clock for the whole file —
  `FENIX_TEAM_CLOCK_MS` (optional env) seeds the fixture AND rides to the
  spawned server through the seam; unset it is the fixture's NOW (pinned,
  never Date.now()). `run-dev-old` keeps its >30d offset by construction.
  The registry fixture stays real-clock-relative (collectChildren's 24 h
  retention reads the real Date.now()), so the ticket-scope children check
  is clock-independent on its own.
- Far-future proof: `FENIX_TEAM_CLOCK_MS=<2027-06-01T12:00Z ms>` run —
  15/15 green with the payload clock ~7.6 months ahead (evidence:
  team-routes-farfuture.txt).

Same-commit fix for the work-routes latent instance (sweep class): the
`/api/costs` kpis assertion (work-routes.test.mjs ~line 436) compares the
spawned server's 30d payload against a window-unbounded per-run number, with
fixture data fixed at 2026-10-13 — ages out ~2026-11-12. The injected clock
does not fit this pipeline cheaply: three separate real-clock consumers
(collectTicketFacts' 30d facts window, the cost-snapshot child's windows, the
5-min stale label vs computedAt) — pinning the snapshot clock alone would
flip `stale` to true, and pinning all of them is disproportionate for a test.
So the fixture clock is DERIVED from the real `Date.now()` at module load —
every timestamp a fixed offset behind it (same deltas as the old fixed
dates) — making the whole pipeline self-consistent and age-proof: 96/96.
