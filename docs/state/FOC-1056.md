### Recon summary (verified against the tree)

- `resolveRole()` (`scripts/agent-state-resolve.mjs`) walks the registry, runs
  per-key resolvers, and turns askable missing keys into one hold per
  namespace. Unresolved keys land in `missing` with reason `"unresolved"` or
  `"depends on <key>"`; the hold question named only the bare key list:
  `Working state (<role>, <namespace>): no deterministic source for <keys>. Answer with one key=value per line.`
- The marker strings `"no deterministic source for "` / `". Answer"` are
  load-bearing: `askedKeysOf()` parses the key list back out for hold dedup.
- Holds are written only when the run dir exists (`ensureRunDir` runs at
  launch, before the SessionStart hook fires) — on a real first run the hold
  IS written; `holdSkipped: "no run dir"` is the degenerate case only. Recon's
  open question resolved: the symptom is the hold itself, not a skip.
- The shipped `docs/STATE.md` carries NO `Active issue` / `Queue head` /
  `Known reds` lines, so on a pristine install the state-md keys have no
  deterministic source. The hook runs offline (Linear credentials stripped),
  so the linear keys can never resolve inside it.
- `fenix-seed-agents.mjs` is squad-config seeding only — not a key seam. The
  existing spawn-time seeding path (`seedPinnedState`) covers child namespaces
  at spawn; the Supervisor's own namespace has no spawn moment.

### Design decision — seed vs precise hold

- **No seeding added.** `seedPinnedState` fires at child spawn with values the
  spawn already renders; the supervisor's first run has no such moment, and
  none of the five askable keys has a deterministic value a fresh install
  could produce without inventing one. Seeding would have meant guessing.
- **Precise hold for all five askable keys.** The fix is wording only: the
  question now appends one `- <key>: <where>` line per asked key, derived from
  the key's own registry resolvers (never hardcoded key names):
  - `state-md` → `docs/STATE.md line "- <label>: <value>"`
  - `env` → `environment variable <NAME>`
  - `linear` → `Linear (issue <issueKey> → <field>), once a Linear API key is available`
  - anything else → `answer here as key=value` (fallback; unused by the
    current registry's askable keys)
- The hints sit AFTER the `". Answer"` marker, so `askedKeysOf()` keeps
  parsing the key list out of the first line — old and new wordings dedup
  against each other, and existing holds stay parseable.
- The registry was NOT edited (Mateusz-owned). The wording derives from
  resolver metadata the registry already carries.
