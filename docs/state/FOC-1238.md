## 2026-11-04 12:20 — decision: (a) host-side archive

Measured on FOC-1159 TEST (run c0cd): the container gate and a host `test-all` ran at once on
one TEST worktree; the script's linked-worktree branch tarred the LIVE tree and caught
`bin/dev-dry.bat` mid-rewrite — run 1 came back 216/218 with two test names cut off. A
justified retry was green: the candidate was fine, the flake is environmental.

**Decision: (a) — the gate proves the COMMITTED candidate.** `fenix test` (`cmd_test`) now
archives HEAD on the host (`git archive --format=tar`) into `.state/tmp/`, mounts the tarball
read-only (`-v <archive>:/src.tar:ro`) and sets `FENIX_TEST_ARCHIVE=/src.tar`;
`docker/test-in-container.sh` takes a new FIRST branch that extracts the tarball as the
throwaway repository. Why (a) and not (b):
- (b) (rule text only) leaves the racy mechanism in place — any caller that skips the rule
  re-introduces the flake; the rule also cannot say "run alone" to CI (which runs the same
  script on a shared checkout).
- (a) is a small change: one branch in the script (~7 lines), archive+mount in `cmd_test`
  (~12 lines), the command text in two rule surfaces + the verdict hint + the dry-run kickoff.
- HEAD-only semantics are the point, not a gap: per FOC-1222 the candidate TEST judges is a
  commit, not the working tree. A dirty checkout now gets an explicit INFO line naming the
  commit tested (the old clone branch overlaid uncommitted work silently — that overlay is
  exactly what made the gate sensitive to host writes).

Untouched on purpose: `.github/workflows/linux.yml` keeps the bare form — CI's checkout is a
real git dir (clone branch) and nothing writes into it during the run, so there is no race to
fix there. Historical docs (`docs/plans/*`, `docs/state/*`) and generic mentions
(`config/graph.json`, `config/prompts.json`, `agents/test/agents/*.md`) name the script, not
the command form — left as is.
