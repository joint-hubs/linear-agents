## 2026-11-02 — Chosen harness form: deny entries, not a PreToolUse hook

The generated per-child settings (`buildChildSettings`, scripts/supervisor-lib.mjs)
now carry two more entries in its self-appended SUPERVISOR_DENY block, so every
child gets them regardless of squad settings or `--settings` extras:

    "Agent(isolation:worktree)",
    "EnterWorktree"

Schema evidence (https://code.claude.com/docs/en/permissions.md): deny rules
match top-level tool input parameters as `Tool(param:value)`, and the docs give
`Agent(isolation:worktree)` as a canonical example ("Agent calls that request a
git worktree"). A parameter the model omits is never matched, so plain
subagent calls stay allowed. `EnterWorktree` is the dedicated tool for the same
move and needs its own bare-name entry (bare tool-name deny matches all uses);
the Agent rule alone does not cover it. Why not a PreToolUse hook: a hook fires
on every Agent call to decide what a static rule already decides — deny rules
apply immediately via `--settings` and cost nothing per call. Both spawn-side
deny derivations (the settings write at supervisor-spawn.mjs:877 and the spawn
result's `deny` field at :1335) go through `buildChildSettings`, so they picked
the entries up with no spawn-side edit.

## 2026-11-02 — Real refused-call evidence

Settings file built with the real `buildChildSettings({})`, written to the OS
temp dir; `claude` 2.1.314 headless (`claude -p`), cwd = temp dir (never the
main checkout), same env both runs.

- **With the generated settings** (`--settings child-settings.json`), prompt
  "Call the Agent tool now to launch a subagent with isolation: \"worktree\"":
  the model made a real `Agent` tool call with `isolation: "worktree"` and the
  harness refused it — `permission_denials` carries exactly that call
  (`tool_name: "Agent"`, input includes `isolation: "worktree"`),
  `subagent_stats.spawned: 0`. Full real-child refusal CAPTURED.
- **Control, same prompt, without `--settings`**: `permission_denials` empty and
  the harness actually proceeded down the worktree-isolation path — its own
  reply: `Cannot create agent worktree: not in a git repository …` (the temp cwd
  is not a git repo, which is what kept the control from creating anything). So
  the denial is attributable to the generated file, not to ambient behavior.
- **`EnterWorktree` attempt with the settings**: the model, asked explicitly,
  answered `TOOL NOT OFFERED` — claude 2.1.314 does not offer that tool in this
  environment, so there was nothing for the deny rule to refuse. Evidence level
  for this entry: settings accepted by the harness + JSON-level pin only, NOT a
  real-child refusal. Honest gap, recorded as such.
