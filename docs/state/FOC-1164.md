# FOC-1164 — one shared hermeticEnv() test helper; status + cleanup suites isolated from host seams

Status: done (implemented, verified, committed)

## Helper semantics

`hermeticEnv(extra)` lives in `scripts/supervisor-test-fixtures.mjs` (add-only export;
`scrubbedEnv`/`baseEnv` untouched). Composition order and what each layer contributes:

1. `baseEnv()` — `scrubbedEnv()` (strips `LA_CHILD_MARK`) + the toolchain seams:
   `OPENROUTER_API_KEY`, `LA_CLAUDE_BIN=mock-claude`, `LA_SUPERVISOR_NO_TELEMETRY=1`,
   `LA_SUPERVISOR_NO_CODEGRAPH=1`, `MOCK_CLAUDE_HANG_MS=0`, `LA_AGENT_STATE_DB`
   (derived from the fixture state home parent, FOC-729). Everything else flows
   through from `process.env` — PATH/HOME survive; identity seams do not.
2. Six identity seams deleted unconditionally:
   `LA_TASK_ID`, `LA_SUPERVISOR_RUN`, `LA_SUPERVISOR_CHILD`, `LA_TASK_OWNER`,
   `FENIX_STAGE`, `FENIX_SUPERVISOR_SESSION_ID`.
3. Pins applied last, then `extra` wins — a test that deliberately wants a seam
   (`LA_TASK_ID` for journal tests, `LA_SUPERVISOR_CHILD` for the refusal test)
   passes it in `extra` and it sticks.
4. Pinned roots:
   - `LA_SUPERVISOR_STATE_HOME` → the fixture home (the value baseEnv already
     resolves; per-suite by construction — the module takes the seam over at load).
   - `LA_DATA_HOME`, `LA_STATE_ROOT` → fresh temp dirs, lazily created per process
     (per-suite, not per-call: suites share fixture run dirs across the whole
     process, so per-call pins would strand every spawn from every fixture;
     deterministic emptiness is the property under test, and `cleanupLater`
     removes them at drain).

Stripped is identity, not the toolchain: the spawned children still get the mock
claude, the telemetry/codegraph guards, and a real PATH.

## Per-suite isolation spawn (item 4)

Done via the byte-identical assertion inside the cleanup suite's retention test
(`run retention drops the run's namespaces and reports them in the summary`): the fake
state home now also carries a LIVE run (`run-new`) with working state under
`child:run-new/dev-1`. A recursive snapshot (relative path → file bytes, via a local
`dirSnapshot` helper) is taken BEFORE the prune and deep-compared AFTER, both inside
the test body — before any `cleanupLater` drain can remove the home. The ancient run
(`run-old`) is deleted by design; the boundary is drawn at the live run's namespace
and now holds on disk too, not just in the agent-state store.
