## `scripts/test-timings.json` — decision: TRACKED

The ticket's intent, and the load-bearing reason: a fresh CI checkout must get the
longest-first order from its FIRST run — a gitignored file makes every cold checkout fall back
to name order exactly where the wall-clock target lives, and the recorded order is a cache
entry, not machine state (CI regenerates it on its first full run and every run after). The
numbers are environment-dependent, so the tests pin ORDERING with a fixture file, never with
live measured values, and only full completed selections regenerate the file — drift stays
bounded by one run. Committed from AFTER run 2 (219 entries).
