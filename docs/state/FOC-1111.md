## 2026-11-01 — queued chat feedback + server-side duplicate-send guard (S44, FOC-789 acceptance day 5)

What: a chat message sent from the Cockpit while the Supervisor's turn runs showed
no usable feedback — on `fenix-accept` the same text was pasted twice and the
Supervisor answered it twice.

- **Server (`scripts/supervisor-host.mjs`)**: `sendLocked` now keeps a per-host
  map of queued-but-not-proven-delivered texts (FOC-1111 duplicate guard). A send
  whose cleaned text equals a still-queued entry is refused with
  `{ sent: false, duplicate: true, queued: true }` (HTTP 200) and is NOT pasted;
  the entry is registered when a send returns `queued`, and pruned lazily at the
  next send.
- **UI (`ui/src/cockpitModel.js`, `ui/src/components/cockpit/ChatView.jsx`)**:
  `sendFeedback`/`pendingAfterSend` classify the send response; the pending chip
  now shows `delivered` when the response carried `confirmed: true` (previously
  it kept saying "sent — not confirmed yet" even though the pane had taken the
  message — the AC1 gap). `duplicate: true` removes the pending line, restores
  the typed text into the composer and shows the warning banner "Already queued —
  it will be delivered when the current turn ends.". JSX stays thin; all
  classification lives in the pure model, unit-tested in `ui/src/_tests_cockpit.mjs`.

Dedupe design decision (delivered-confirmation, not a primary TTL):
- Scope: the state lives in the `createHost` closure — one host instance per
  session (the managed task-session hosts each build their own; the legacy host
  is the one global session), so the dedupe is per-session by construction and
  the scoped `/sessions/:sid/message` route is covered for free (verified:
  `task-session-host.mjs` builds one `createHost` per controller). Two dashboard
  tabs hit the same host and share the map.
- Key: exact cleaned text (the same normalization the paste gets). The send
  mutex serializes `sendMessage = serialized(() => sendLocked(text))`, so only
  `sendLocked` touches the map.
- Delivery proof: a hook write in state `busy` with `updatedAt` AFTER the queue
  time — a prompt was taken since, and queued inputs are consumed in order, so
  ours went with it. An `idle` or `needs-input` write is deliberately NOT proof:
  the turn we queued behind can Stop or ask for permission without the queued
  input having been submitted yet; clearing on those would re-open the
  double-delivery. Consequence: keys clear lazily at the NEXT send (or the TTL),
  not at the exact delivery instant.
- Between-sends race (first delivered, then the resend): send A queues behind
  turn T1; T1 ends and consumes A (UserPromptSubmit writes `busy`, fresh
  updatedAt > A's queue time); a second send of the same text prunes the key at
  entry and goes through — legitimate, pasted again behind whatever turn is now
  running. Tested explicitly ("delivered message frees the key").
- TTL backstop (`QUEUED_DEDUPE_TTL_MS`, 15 min): a key whose queued input was
  silently lost (an Esc-cancelled turn never fires Stop and discards the queued
  input) would otherwise block honest resends forever. Trade-off, cited: a turn
  running LONGER than 15 min with the text still queued re-allows a duplicate
  resend after the TTL — accepted because the UI warning still fires and the
  alternative (no TTL) is a permanent dead-end for a lost message.
- A fresh session start (absent → started, or `fresh: true` kill+start) clears
  the map: the pane the texts were pasted into no longer exists.

Model surface added (`ui/src/cockpitModel.js`):
- `sendFeedback(res)` → `{ kind: duplicate|delivered|queued|sent, state }` —
  server response is the source of truth; unrecognized shapes degrade to `sent`.
- `pendingAfterSend(prev, res, id)` → pending lines after the response
  (state transition; duplicate removes the line).
- `duplicateWarning(res)` → `{ text }` banner payload or null.
- `pendingChip(state)` → the chip label (queued / delivered / sent fallback).

   carried `confirmed: true`) until the transcript shows the line.

   banner "Already queued — it will be delivered when the current turn ends.",
