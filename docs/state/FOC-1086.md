# FOC-1086 — cleanup_remove leaves stale workspace claims

Journal (append-only). First entry: the implementing dev run on branch
`foc-1086-dev-63dbd3e17f60`, base `65e5e4e`.

## Recon finding — where the removal path skipped the claim

`scripts/supervisor-cleanup.mjs` `remove` → `cmdRemove` has three paths that end
with a removed (or already-gone) worktree, and none of them touched
`<commonGitDir>/workspace-claims/claims.json`:

1. the recorded-grant path — `cmdRemove` → `performRemoval` (was line ~867);
2. the two-key path (TEST approval + answered cleanup gate) — also
   `performRemoval` (was line ~955);
3. the already-removed branch (`!existsSync(entry.worktree)`, was lines
   ~803-830) — its own JSON blob, no claim handling at all.

`performRemoval` did `unlinkReparsePoints` → `git worktree remove` →
`updateChild(worktreeRemovedAt …)` and printed the honesty report — the claim
registry was never read. A claim on a removed worktree is stale by definition
and blocks a future Supervisor from the same branch name (the FOC-898 collision
guard); observed on Docker rc.8 (FOC-789): worktrees gone, claims stayed behind.

Fix shape: a new `releaseClaimsForWorktree({ gitRoot, worktree })` in
`scripts/workspace-claims.mjs` — worktree-path-keyed (samePath normalization),
owner-INDEPENDENT, because a stale claim's owner may be an old run nobody can
release as. `releaseClaim`'s owner-keyed semantics are unchanged. Both
`performRemoval` and the already-removed branch call it after the removal
succeeded (a refused removal leaves the claim standing, like the worktree it
vouches for); a release failure is best-effort (stderr note, empty list) — the
removal has already happened, so it must not failJson the command away.

## AC-1 — removal releases the claim on all three paths

`releasedClaims` (additive key, `[{ branch, ownerId }]`) appears in the
`performRemoval` report and in the already-removed blob; matching uses the
claims module's `samePath` normalization, claims on other worktrees are
untouched. Verified by the four FOC-1086 tests in
`scripts/supervisor-autonomy.test.mjs` (grant path, two-key path,
already-removed via `--repo`, and the untouched-neighbour claim).

## AC-2 — doctor warns on stale claims

`fenix doctor` gained a `workspace claims` check
(`checkWorkspaceClaims` in `scripts/fenix-doctor.mjs`, loaded through the
FOC-1068 loadHelper seam, wired after `run owners` in `runChecks`). Reads the
claims registry of the repo root resolved from the script's own checkout; warn
line format:

```
WARN workspace claims — 2 claim(s) name worktrees that no longer exist: <p1>, <p2>, <p3>, … +N more — a stale claim blocks a future Supervisor from the same branch — fix: re-run cleanup remove for the removed child (it releases the claim), or release it through the claims registry
```

ok when every claimed worktree exists and when there is no claims file at all;
an unreadable registry warns (fail-closed read surfaces as a warn, never a
crash). Tests in `scripts/fenix-doctor.test.mjs` (seam-injected + real fixture
repo through `claimWorkspace`).
