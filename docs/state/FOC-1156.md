## Item 2 — marker `node_modules/.fenix-install-ok`

Problem: a partial `node_modules` survives a failed or timed-out install and
the next `ensure` skipped it forever as "already present".

Implementation (`scripts/supervisor-lib.mjs`):

- `installDepsAt` stamps `node_modules/.fenix-install-ok` ONLY when the
  bounded install exits 0 (`runBoundedInstall` result `code === 0`); a failed
  or timed-out run leaves the tree without the marker. A marker write that
  itself fails is swallowed by design — a missing marker is the safe
  direction (the next ensure reinstalls rather than skips).
- The skip branch now requires the marker: `node_modules` present as a real
  directory WITHOUT it is stale — it falls through to the removal branch
  (`rmSync`) and a fresh install. The removal keeps the existing
  reparse-point discipline: `isReparsePoint` (the check shared with
  `supervisor-cleanup.mjs`'s prior art) decides, and `rmSync` unlinks a
  reparse point AS A LINK, never following it; a stale real directory is
  removed recursively (`rmSync(nm, { recursive: true, force: true })`).
- The record distinguishes the shapes: `replacedObstruction` (link or stray
  file, unchanged semantics) vs the new `removedStale` (marker-less tree).

scripts/supervisor-spawn.test.mjs`):

The timeout in the timed-out test uses the existing `LA_DEPS_INSTALL_TIMEOUT_MS`
seam (8 s) — no real 300 s waits; the residue is planted deterministically if

lockfile `npm ci` accepts) is the FOC-1153 suite's own.

Consequence for the pre-existing r2 skip test: it now plants the marker too
(the new fast-path contract), same file, updated in this change.

## Item 3 — `*_KILL_MS` naming convention (implemented, small)

The wait-budget scan now recognizes `*_KILL_MS` constants and exempts them by
name — a constant so named is a subprocess kill-timeout by construction, so
the next kill-timeout constant needs no allowlist edit. The default posture is
unchanged: an unlisted `*TIMEOUT_MS` above 120 s still fails (pinned by the
existing TEST-r1 test, untouched).

Red-first fallback (structural reason): the convention test cannot be made to
fail on base. On base the scan regex
`\b([A-Z_]*(?:TIMEOUT_MS|POLL_MS|WAIT_MS)[A-Z_]*)\s*=\s*([0-9][0-9_]*)` never
matched a `KILL_MS` name at all, so "unscanned" and "explicitly allowed" are
indistinguishable in the violations output — both yield `[]`. The change makes
the convention explicit and pins it: if the suffix list is later extended
without the exemption, the test fails instead of the convention silently
regressing.

## Item 4 — `killFailed` branch of `runBoundedInstall`: DECLINED

The branch fires only when the timeout's tree kill does NOT land while the
child stays alive (`close` never fires; the grace timer resolves with
`killFailed: true`). Testing it deterministically needs one of:

- an injection seam for `killTree` — there is none; `runBoundedInstall` calls
  the in-module `killTree` directly, so this is a production-shape change,
  beyond the item's "cheap seam" bar; or
- a child process that deterministically survives a forced tree kill — not
  producible from a test on this platform (win32 `taskkill /F` succeeds for
  any process the test user owns; POSIX SIGKILL to an own process group
  cannot be blocked).

Declined; the branch is unchanged. The existing orphan test pins the normal
timeout path (the tree kill lands, `close` wins the race, no `killFailed`
flag on the record).
