# FOC-771 — Node entry points replace the .bat launchers (cross-platform)

Owner: delivery owner (orchestrator), 2026-10-16. Branch `foc-771-node-launchers`, cut from `main` at #71. Parent FOC-768 (M8). 22 Windows `.bat` launchers own startup; a container or a macOS/Linux developer cannot use them. In the container the Supervisor (`docker/entrypoint.sh supervisor-run` → `supervisor-launch.mjs`) and every child (`supervisor-spawn.mjs`) already start without `.bat` — the gap is the host side: the interactive frontman, the standalone squads, the dry runs and `agent.bat`.

## Facts (recon 2026-10-16)

- `bin/_lib.bat` does, in order: ROOT; cost-guard check (`scripts/cost-guard.mjs check`, skipped for the supervisor); `.env` load with the window-level `LINEAR_TEAM_KEY`/`LINEAR_WORKSPACE` preserved; atlas-mcp render (template → `config/atlas-mcp.json` when missing); new-team provisioning marker (`.state/teams/<KEY>.provisioned`, `bootstrap-linear.mjs --check`, y/N prompt); NATIVE mode clears every `ANTHROPIC_*`, otherwise `provider-resolve.mjs --check` (fail-closed) and the `set` lines are applied; `CLAUDE_CODE_SUBAGENT_MODEL` cleared; `API_TIMEOUT_MS=3000000`; run manifest `gen-id <squad>` → `start <runId> <squad> <sourcePath>`; the launcher calls `end`.
- Each squad launcher sets `CLAUDE_CONFIG_DIR=agents\<squad>`, a hardcoded `ANTHROPIC_MODEL` (edited by the dashboard through `scripts/squad-config.mjs` regex anchors in `bin/<squad>.bat` + `<squad>-dry.bat`), echoes status, runs bare `claude %*`. `supervisor.bat` adds `LA_SUPERVISOR_REPO=%CD%`, `SUPERVISOR_MODEL` (NATIVE → opus ids, else `xiaomi/mimo-v2.6-pro`), `LA_SUPERVISOR_RUN` = RUN_ID, `supervisor-current-run.mjs record`. `*-dry.bat` set `<SQUAD>_DRY_RUN=1` and run `claude -p "<kickoff>" --permission-mode default --max-turns 40` (dev adds `scripts/check.mjs`). `agent.bat <area> <role>` takes the model from `config/models.map`, hardcodes anthropic tiers and binds the role with `--append-system-prompt`. `orchestrate.bat` is dead (FOC-288 guard); `all.bat`, `dashboard*.bat`, `dashboard-stop.bat` are Windows tooling.
- Node side: `provider-resolve.mjs` (`resolveProvider`, `formatSetLines`, `parseEnvFile`), `child-model.mjs` (`childModelFor` = the routing table + overlay `routing.<squad>.lead`, FOC-762; `childProviderEnv`), `fenix-paths.mjs` (`squadConfigDir`, `stateRoot`), `run-manifest.mjs` (CLI only), `agent-launch-profile.mjs` (container config-dir profile), `launch.mjs` (dashboard Start button: `buildLaunchBat` writes a wrapper that `call`s `bin/<squad>.bat`; `launchSupported = win32 && !container`).
- Tests that pin today's shape: `config-drift.test.mjs:318-331` (lead model in every `bin/<squad>.bat` has a price), `squad-config-write.test.mjs:194-236` (writing the lead touches `dev.bat` + `dev-dry.bat`, plan's NATIVE branch untouched), `squad-config.mjs:70-149,484-495` (regex anchors).

## Design

1. **One entry point** `scripts/squad-start.mjs <plan|dev|review|test|cadence|supervisor> [--dry-run] [--native] [--task <id>] [--source <path>] [--print-plan] [-- <claude args…>]` and `--agent <area> <role>` (the `agent.bat` case). A pure `planLaunch({ squad, mode, env, cwd, root, tty })` returns `{ env, configDir, model, claudeArgs, manifest: { squad, sourcePath, headless }, checks: [...] }` without side effects; `runLaunch(plan, { spawn, runManifest, prompt })` performs them in `_lib.bat` order: cost-guard (skipped for the supervisor), `.env` load (window-level `LINEAR_TEAM_KEY`/`LINEAR_WORKSPACE` win, everything else from `.env` overrides, exactly as `_lib.bat`), atlas render (same rule as today on this branch; the FOC-772 integrations gate lands when #81 merges), provisioning marker with the y/N prompt only on a TTY (otherwise one line and skip), NATIVE → clear `ANTHROPIC_*`, else `resolveProvider` fail-closed and its env applied, `CLAUDE_CODE_SUBAGENT_MODEL` cleared, `API_TIMEOUT_MS`, run manifest `gen-id` → `start` (`--headless` for dry runs), `claude` with inherited stdio, `end` in `finally` (also on signals), exit code passed through. `--print-plan` prints the plan as JSON and exits 0 (tests and the dashboard use it).
2. **Models from data, not from .bat lines**: the lead model is `childModelFor({ squad })` (routing table + overlay), the same source the children use; the supervisor's model is `SUPERVISOR_MODEL` env > `routing.supervisor.lead` > the current default; NATIVE keeps today's opus ids per squad in `config/native-models.json` (data). `--agent` reads `config/models.map` as today. Dry-run kickoffs move from the `.bat` bodies into `config/dry-run-kickoffs.json` verbatim.
3. **Dashboard model editing** (`scripts/squad-config.mjs`): reads the lead from the routing sources (overlay > `config/models.json routing.<squad>.lead`) and writes through `fenix-settings` (`routing.<squad>.lead`), no `.bat` parsing; the provider read stays through `provider-resolve`. `config-drift.test.mjs` pins "the lead model of every squad in the routing table has a price" instead of grepping `.bat` lines. `launch.mjs` keeps writing its wrapper `.bat` on Windows (it `call`s `bin/<squad>.bat`, which stays a wrapper); POSIX launch from the dashboard is FOC-777's scope.
4. **`.bat` files become wrappers**: `bin/<squad>.bat` = `@node "%~dp0..\scripts\squad-start.mjs" <squad> %*`; `<squad>-dry.bat` passes `--dry-run`; `plan-native.bat`/`supervisor-native.bat` pass `--native`; `agent.bat` passes `--agent %1 %2`; `supervisor.bat` keeps its header comment and `LA_SUPERVISOR_REPO` comes from the Node side (`cwd`). `orchestrate.bat` is deleted (dead since FOC-288); `orchestrate-openrouter.bat`, `all.bat`, `dashboard*.bat` stay as they are (Windows tooling, out of scope). A test asserts every squad wrapper is the two-line shape.
5. **Docs**: README (standalone launchers: `node scripts/squad-start.mjs dev` on any OS, `bin\dev.bat` on Windows), QUICKSTART, CONTRIBUTING, docs/00-overview, docs/ACCESS (`bin\agent.bat` still works), agents/*/CLAUDE.md mentions of `bin\agent.bat` stay valid (wrapper).

## Acceptance (ticket)

1. `node scripts/squad-start.mjs <squad> --print-plan` on Windows and Linux yields the same env/args shape; the Linux lane runs the plan tests; the Supervisor starts through the entry point on Windows (`bin\supervisor.bat` wrapper) — manual check by Mateusz on the next run; in the container nothing changes (already Node).
2. `config-drift` and `squad-config` tests cover the new entry point and the routing-based lead; the dashboard's Provider & routing screen edits the same key `squad-config` now writes.
3. Run-manifest sequence and provider env pinned by tests (fake `spawn` recording argv/env): `gen-id` → `start [--headless]` → claude → `end`, `end` on claude failure too; NATIVE clears `ANTHROPIC_*`; provider failure → exit 1 before any manifest write.

## Out of scope

The `fenix` user CLI (FOC-777), POSIX launch from the dashboard Start button, `all.bat`/dashboard batch tooling, the FOC-772 integrations gate in the atlas render (lands with #81).
