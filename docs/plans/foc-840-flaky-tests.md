# FOC-840 — flaky tests under suite load: deterministic waits, child cleanup, suite-level orphan sweep

Owner: delivery owner (orchestrator), 2026-10-16. Branch `foc-840-flaky-tests`, cut from `main` at #71. Parent FOC-472 (maintenance). Seen 2026-10-13 → 10-16 on Windows and in the Linux lane: `supervisor-wake` "superseded mid-wait" red ~1 in 8, `mcp-enable` case-variant key red once under load, a real `telemetry-server.mjs` left alive 34 h after its test run.

## Facts (recon 2026-10-16)

- **supervisor-wake**: the test spawns the waker, `sleep(500)`, writes a newer lease, expects exit 0 within 1.5 s (`supervisor-wake.test.mjs:264-277`). Two races: (A) under load node startup can exceed 500 ms, the test's newer lease lands first and the waker's own arm-write (`supervisor-wake.mjs:230`) overwrites it — supersession never happens; (B) the waker's heartbeat (`:307`) writes the lease object it read at the top of the loop, so a newer lease written inside the read→write window is clobbered — the next loop top sees its own pid again and the waker runs to the lifetime (exit 2). (B) is a production bug: a superseded waker resurrects its lease and outlives the takeover. Observed 2 failures in 12 standalone runs.
- **mcp-enable**: the fixture is already a per-test mkdtemp; no test sets HOME/USERPROFILE/CLAUDE_CONFIG_DIR; the only nondeterminism channel is `cliProjectKey` falling back to the resolved literal when `realpathSync` throws (`mcp-enable.mjs:85-93`) while the test's own `realpathSync` succeeded (8.3/short-name tmp paths) — the seeded key and the expectation must derive from one realpath, or the assertion must use `sameDir`.
- **Orphans**: `scripts/spawn-isolated.mjs` does not exist; the pattern lives in `spawnIsolatedServer` (`settings-acceptance.mjs:746-768`) and five inline copies in route tests (settings-routes, cockpit-routes, work-routes, task-cockpit-routes, telemetry-analysis-api) plus a module-level child in `rewards-routes.test.mjs:95` whose teardown is a bare top-level await. None installs SIGINT/SIGTERM/exit/unhandledRejection handlers; `child.kill()` kills the direct pid only. `test-run.mjs killInFlight` (`:248-256`) kills only the test-file process on a budget trip — every grandchild (server, waker, mock) is orphaned. `killTree(pid, mode)` exists in `supervisor-lib.mjs:2200-2214` (taskkill /T on win32, process-group kill on POSIX; children must be spawned `detached: true` on POSIX to lead a group).
- `zz-suite-env-scrub.test.mjs` is a parallel-lane file, so a "last" test cannot run after the lanes; the runner itself must sweep after `Promise.all([parallelRun, serialRun])` (`test-run.mjs:330-334`).

## Design

1. **Waker stand-down is compare-and-swap** (`scripts/supervisor-wake.mjs`): before every lease write (arm excluded, heartbeat and endedAt included) re-read the on-disk lease; if its pid is not ours, stand down with exit 0 and no write. The arm-write stays, but the loop's first read happens right after it, so a newer lease landing before the arm is detected on the first heartbeat. Test rewrite (`supervisor-wake.test.mjs`): replace `sleep(500)` with a poll (10 ms step, 5 s cap) until the lease file carries the spawned waker's pid, then write the newer lease; add a test that writes the newer lease between the waker's read and heartbeat (drive it with POLL_MS large and a lease written right after the first heartbeat is observed) and asserts exit 0 with the newer lease untouched. Proof: 30× loop of the file on Windows and in the Linux lane.
2. **mcp-enable**: the case-variant test seeds its key from the same `realpathSync` the CLI uses (import `cliProjectKey` or compute both sides from one helper) and asserts survival with `sameDir`; no fixture sharing.
3. **One spawn helper for real servers** — `scripts/test-spawn.mjs`: `spawnTestServer({ script, args, env, healthUrl, timeoutMs })` → `{ child, port, stop() }`: probes a free port, spawns `detached: process.platform !== "win32"`, polls the health URL, appends `{ pid, port, script, file: <caller test file>, startedAt }` to the registry file named by `LA_TEST_SPAWN_REGISTRY` (when set), and installs — once per process — `SIGINT`/`SIGTERM`/`SIGHUP`/`exit`/`uncaughtException`/`unhandledRejection` handlers that `killTree` every live child it spawned; `stop()` tree-kills, waits for exit (bounded), and removes the registry row. `settings-acceptance.mjs spawnIsolatedServer` and the six test-file copies move onto it; `rewards-routes.test.mjs` gets a `finally`.
4. **Runner sweep** (`scripts/test-run.mjs`): the runner creates `LA_TEST_SPAWN_REGISTRY=<runTmp>/spawns.jsonl` and passes it to every test-file child; `killInFlight` switches to `killTree`; after both lanes resolve, the runner reads the registry, probes each pid (`tasklist /FI "PID eq N"` on win32, `process.kill(pid, 0)` on POSIX), tree-kills survivors and FAILS the run with `test orphans left running: <file> pid N port P (killed)`; the budget's `onKill` runs the same sweep. `test-run.test.mjs` covers: a fake test file that spawns a sleeping child through the helper and exits without stopping it → the run is red with the orphan line and the child is dead afterwards; a clean run → no sweep output.
5. Docs: this plan; `docs/supervisor-e2e-checklist.md` test-file count if a test file is added; a line in the e2e checklist's suite section about the sweep.

## Acceptance (ticket)

1. `supervisor-wake.test.mjs` and `mcp-enable.test.mjs` 30× green on Windows and in the Linux lane (loop scripts in the PR body).
2. Every real-server spawn in tests goes through `test-spawn.mjs`; killing a test file mid-run (SIGTERM on POSIX, taskkill on win32) leaves no server alive — covered by the helper's test.

## Revisions (implementation + review, 2026-10-16)

- **Lock layer on top of the CAS (item 1).** The CAS alone still lost 1/30 container runs: the re-read and the write were two steps and a competing writer could land between them. `supervisor-lib.mjs` adds `waker.json.lock` (mkdir lock; 2 s bounded wait, stale recovery by mtime after 5 s, release retried up to 5×); `writeWakerLease` and `updateWakerLease` hold it across read and write, and the waker's ownership check runs inside it. On win32 `EPERM`/`EACCES`/`ENOTEMPTY`/`EBUSY` on the lock dir count as "held" (create-vs-delete and AV-handle races), not as errors.
- **A thrown lease write is not "superseded".** The waker retries a failed write on the next poll and exits 1 after five consecutive failures; only an ownership loss (the lease on disk is someone else's) stands it down with exit 0.
- **Helper (item 3).** `detached: true` on every platform (not only POSIX) so the server's lifetime never depends on the parent's handles; `windowsHide: true`. Options added: `port` (explicit fixed port, used by `rewards-routes`), `inheritEnv: false` (callers that build the full child env, `cockpit`/`task-cockpit`, keep their deleted keys deleted). `stop()` appends a tombstone instead of rewriting the registry (append-only JSONL is the only interleaving-safe operation across parallel lanes; `openRegistryRows` folds spawn rows and tombstones in file order) and THROWS when the child survived the kill — the row stays for the sweep.
- **Runner (item 4).** The budget-kill sweep runs silently (the dying trees may not be reaped yet); the final sweep after both lanes reports what is still alive. The probe is pid-only — a pid reused inside one run would be tree-killed; rows carry `startedAt` if that ever needs closing. The per-run temp dir is removed on process exit.
- **Race-B test.** It pins the guarded-write semantics at an arbitrary write time; the read→write window itself is closed by the lock and exercised by the 30× loops, not deterministically by a test.
