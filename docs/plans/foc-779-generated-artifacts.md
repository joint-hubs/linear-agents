## Design

1. **Registry** `config/artifacts.json` (committed): `{ "version": 1, "artifacts": [ { id, title, output, sources: [globs relative to the repo], generator: { cmd: [...] } | null, refresh: "start" | "watch" | "launcher" | "external", committed: boolean, inContainer: boolean, notes } ] }`. Entries now:
   - `models-map`: output `config/models.map`, sources `config/models.json`, generator `node scripts/gen-model-map.mjs`, refresh `watch`, committed false (this PR stops committing it: `git rm --cached`, `.gitignore`; `bin/_lib.bat` regenerates it when missing or older than `models.json`, the way it renders `atlas-mcp.json`).
   - `ui-dist`: output `ui/dist`, sources `ui/src/**`, `ui/index.html`, `ui/package-lock.json`, `ui/vite.config.*`, generator `npm --prefix ui run build`, refresh `watch`, inContainer false (the image ships it prebuilt; in the container the entry is reported, never rebuilt).
   - `atlas-mcp`: output `config/atlas-mcp.json`, sources its template, generator null, refresh `launcher` (reported only; the launcher renders it).
   - `diagrams-png`: output `docs/diagrams/*.png`, sources `docs/diagrams/*.puml`, generator `sh scripts/render-diagrams.sh`, refresh `external`, committed true — the documented exception: the PNGs stay in git so GitHub readers see them and the renderer needs Java; the registry only labels them stale.
   - `codegraph-index` and `analysis-cache`: refresh `external`, status delegated (`code-intel.mjs status` verdict / the cache status) — reported, never managed here.
2. **Module** `scripts/artifact-registry.mjs`: `readRegistry()`; `sourceDigest(entry, { root })` = sha256 over the sorted list of `relative path\0size\0content hash` of the files matched by `sources` (content, not mtime, so a fresh clone matches); `artifactStatus(entry, { root, manifest, head })` → `{ id, title, exists, outputMtime, age, head, digest, manifest: { head, digest, generatedAt } | null, state: "fresh" | "stale" | "missing" | "external", reason, refresh, committed }` — stale when the output is missing (→ `missing`), the manifest entry is missing, or the manifest digest differs; `external` entries report `exists`/`age` and, for codegraph, the status verdict; `refreshArtifacts({ root, only, dryRun, inContainer, now })` runs the generator of every `start`/`watch` entry that is stale (skipping `inContainer: false` entries inside the container), writes the manifest `<dataHome>/artifacts-manifest.json` (gitignored; `LA_ARTIFACTS_MANIFEST` seam) with `{ head, digest, generatedAt, generator }` per id, and returns `{ refreshed: [...], skipped: [{ id, reason }], failed: [{ id, error }] }` — one generator failure never blocks the others. CLI: `status [--json]`, `refresh [--dry-run] [--only id] [--in-container]`; exit 1 when `failed` is non-empty.
3. **Hooks**: `bin/dashboard.bat` runs `node scripts/artifact-registry.mjs refresh` after its UI-build block (so a fresh clone gets every `start`/`watch` artifact before the server starts); `docker/entrypoint.sh` `api` case runs `refresh --in-container` before exec; `bin/_lib.bat` regenerates `models.map` like `atlas-mcp.json`. `telemetry-server.mjs`: every 4th ingest tick (60 s) recomputes statuses (digests are cheap: a few hundred small files) into a cache and, natively, refreshes stale `watch` entries under a lock so a source change regenerates within one cycle; inside the container it only reports.
4. **Route** `GET /api/artifacts` → `{ computedAt, head, artifacts: [status…] }` from the tick cache (fresh compute when the cache is empty); same loopback rules as the other read-only routes.
5. **Dashboard**: Settings → "Artifacts" section (`ui/src/components/settings/ArtifactsPanel.jsx`, registered like Retention in `screens/Settings.jsx` and `navAreas.js`): a table with title, output path, state badge (fresh / stale / missing / external), age, source revision (`head` short + digest short), refresh kind, and the manifest's `generatedAt`; stale rows are labelled, never shown as current; a muted note says where the refresh happens (`fenix up` / dashboard start / 60 s watch). View model + tests in `ui/src/settingsModel.js` / `_tests_settings.mjs`; browser check on an acceptance instance.
6. **Docs**: this plan; `docs/QUICKSTART.md` one line (artifacts regenerate on start; `node scripts/artifact-registry.mjs status`); `.gitignore` comment for `config/models.map`; e2e checklist test-file count for the new test file.
